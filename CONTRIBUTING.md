# Contributing

The **Threat Scenario-Based Detection Use Case Framework** is an evolving methodology. Technical review and reproducible contributions are welcome.

## Useful contributions

Contributions are especially valuable when they:

- identify conceptual inconsistencies;
- improve Detection Capability (CD) or Detection Unit (UD) definitions;
- challenge attack-phase assumptions;
- improve telemetry requirements;
- correct or refine MITRE ATT&CK mappings;
- propose measurable coverage models;
- provide vendor-neutral detection examples;
- improve safe response automation patterns;
- identify overlap or differences with established Detection Engineering or Threat-Informed Defense approaches;
- provide reproducible threat-scenario examples.

## Design principles

Contributions should preserve these principles:

1. The threat scenario remains the primary design and evaluation unit.
2. Detection coverage is more important than raw rule count.
3. CD and UD remain separate methodological layers.
4. Telemetry requirements must be explicit.
5. MITRE ATT&CK is used as a behavior taxonomy, not as a replacement for threat modeling.
6. Automation must consider confidence, operational impact, and reversibility.
7. The framework should remain vendor-neutral.

## Discussion

Use GitHub Issues to propose methodological changes, challenge assumptions, report ambiguity, or suggest reference scenarios.

When proposing a change, describe:

- the problem;
- the current assumption;
- the proposed change;
- expected benefit;
- possible trade-offs;
- evidence or references when available.

## Status

The project is currently **Draft v0.2**. Terminology, metrics, and artifacts may continue to evolve as the methodology is tested against practical scenarios.
